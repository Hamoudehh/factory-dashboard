# דשבורד ייצור – ארומה מאפים

דשבורד למאפייה עם חמש מכונות: רונדו, קרומסטר, פילו, כנול ולחם. הוא מציג KPI למכונות, לעובדים, למוצרים ולמלאי, מראה כמה ימי מלאי יש לכל מוצר מול צריכת הלקוחות, ובונה תוכנית ייצור שבועית אוטומטית. אפשר להזין נתונים ולאפס אותם, והוא עובד בנייד ובמחשב.

האפיון המלא נמצא ב-[SPEC.md](SPEC.md).

## הפעלה

**במחשב:** לחיצה כפולה על `index.html`. הגרפים והגופנים נטענים מהאינטרנט, אז בפעם הראשונה צריך חיבור.

**עם שרת מקומי** (מומלץ לפיתוח):
```bash
node tools/serve.js
```
ואז לפתוח את `http://localhost:5173`.

**בנייד:** בונים קובץ אחד ושולחים אותו לטלפון, או פותחים את קישור ה-Artifact ב-claude.ai.
```bash
node tools/bundle.js
```
הפקודה יוצרת את `dist/factory-dashboard.html` (קובץ אחד עם כל הקוד).

## איפה הנתונים

- **בקישור של claude.ai** הנתונים נשמרים ב-**Airtable**, בבסיס "ארומה - מאפים · דשבורד ייצור". כל מכשיר שפותח את הקישור רואה את אותם נתונים. פרטים בסעיף "Airtable" למטה.
- עותק מקומי נשמר תמיד גם ב-`localStorage` של הדפדפן, תחת המפתח `fd.v1`.
- **בקובץ מקומי** (`index.html`, `tools/serve.js` או `dist/`) אין Airtable. כל דפדפן שומר נתונים משלו, ומעבירים אותם דרך **הגדרות ← גיבוי ושחזור**.
- בפתיחה הראשונה נטענים 30 ימי נתוני דמו עד היום (בכותרת מופיעה תגית "נתוני דמו"). את המוצרים, העובדים ופריטי המלאי עורכים בהגדרות.
- מוצר מוגמר נספר ב**קרטונים**. לכל מוצר מגדירים בהגדרות כמה יחידות יש בקרטון וכמה קרטונים הלקוחות לוקחים ביום.

## Airtable

- הדשבורד מתחבר דרך **מחבר Airtable של claude.ai**, בהרשאות של מי שפותח את הקישור. **אין token בקוד ובדף.**
- כל צופה צריך מחבר Airtable בחשבון claude.ai שלו (Settings ← Connectors), עם גישה לבסיס. בפתיחה הראשונה הדף מבקש אישור לגשת ל-Airtable.
- כשהבסיס ריק, מופיע באנר: **העלה את כל הנתונים**, או **התחל נקי: רק רשימות**.
- כל שינוי נשלח ל-Airtable תוך שנייה בערך. בכותרת מופיע הסטטוס: טוען, שומר, מסונכרן או לא נשמר.
- אם שמירה נכשלת, השינוי נשאר במכשיר ונשלח בטעינה הבאה, או בלחיצה על **הגדרות ← Airtable ← נסה לשמור שוב**.
- טבלה לכל רשימה ולכל סוג דיווח. המיפוי נמצא ב-`js/airtable.js`, וההסבר המלא בסעיף 16 ב-SPEC.

## שעות עבודה

משמרת אחת: 06:00–16:00, ראשון עד חמישי. בשישי עד 12:00. עובדים שנשארים עד 18:00 מסומנים בנוכחות, ומקבלים 2 שעות נוספות. את השעות משנים בהגדרות.

## תוכנית ייצור שבועית

מסך **תוכנית** בונה לבד תוכנית ל-6 ימי העבודה הבאים. לכל מכונה, בכל יום, המוצרים עם הכי מעט ימי מלאי מקבלים את המכונה ראשונים, עד שמגיעים ל-3 ימי מלאי. אם גם אחרי יום מלא נשאר מוצר עם פחות מיום מלאי, המכונה מתוכננת עד 18:00. ההסבר המלא בסעיף 8 ב-SPEC.

## הזנת נתונים

במסך **הזנה** יש ארבעה כפתורים:

| כפתור | מה מזינים |
|---|---|
| דיווח ייצור | מכונה, מוצר, זמן עבודה (עד 16:00 או עד 18:00), מתוכנן/תקין/פחת ייצור, השבתות לפי סיבה, עובדים |
| נוכחות יומית | סטטוס, שעות, ומי נשאר עד 18:00 |
| תנועת מלאי | כניסה, יציאה (למשל משלוח לסניפים, בקרטונים) או פחת |
| ספירת מלאי | כמות שנספרה מול הכמות במערכת |

אחרי כל שמירה מופיע כפתור **בטל** ל-8 שניות. ברשימת הרשומות האחרונות אפשר למחוק רשומה בשתי לחיצות.

## איפוס

**הגדרות ← איפוס נתונים**. יש שלוש אפשרויות: מחיקת תנועות בלבד, חזרה לנתוני דמו, או איפוס מלא. לפני כל איפוס נשמר גיבוי, ואפשר לשחזר אותו מאותו מסך.

## שמירה אוטומטית ל-GitHub

כל שינוי נשמר ונדחף ל-GitHub לבד, דרך `tools/auto-commit.js`:

- **אחרי כל תשובה של Claude:** hook מסוג Stop ב-`.claude/settings.json` מריץ את הסקריפט.
- **כשאתה עורך קבצים בעצמך:** `node tools/auto-commit.js --watch` שומר ודוחף 15 שניות אחרי העריכה האחרונה. עוצרים ב-Ctrl+C.
- **ידנית:** `node tools/auto-commit.js`, או `--dry-run` כדי לראות מה יישמר.

אם בדיקה נכשלת, שום דבר לא נשמר ולא נדחף. ההסבר המלא נמצא בסקיל `.claude/skills/auto-commit-push/SKILL.md`.

## בדיקות

```bash
node --test
```
הבדיקות מכסות את נוסחאות ה-KPI (OEE, מלאי בקרטונים, ימי כיסוי, עלות עבודה, דיוק ספירה), שעות העבודה, התוכנית השבועית, נתוני הדמו, מעבר מגרסה 1, האיפוס, ואת הסנכרון עם Airtable (מול מחבר מדומה). צריך Node 18 ומעלה.
